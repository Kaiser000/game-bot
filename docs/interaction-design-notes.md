# 圆桌智核交互设计记录

这些规则用于 Web Demo，也要延续到后续游戏版本。

## 座位与头像

- 桌面第一视觉是“圆桌”，玩家围绕圆桌分布，而不是列表式房间。
- 每个座位使用头像标记，头像下方显示昵称，再下方显示状态或玩家自己的身份猜测。
- 空座点击用于加入；已入座玩家和 AI 点击用于查看或编辑标记。
- 入座后的自己不再显示一个可移动小人，避免“人已经坐下但还在场景里走”的逻辑冲突。

## 身份标记

- 身份标记是玩家个人推理笔记，不是真实身份展示。
- 标记默认只保存在当前浏览器本地，不同步给其他玩家，不影响后端身份、发言、投票或结算。
- 标记选项要跟随桌游和板子变化：
  - 狼人杀优先提供可疑、狼人、预言家、女巫、猎人、守卫、白痴、村民等。
  - 阿瓦隆优先提供可疑、好人方、坏人方、梅林、派西维尔、莫甘娜、刺客、莫德雷德等。
- UI 文案必须强调这是“私人标记”，避免玩家误以为系统暴露身份。

## 语音交流

- 真人玩家的主交流方式应该是语音，文字输入只作为浏览器不支持、麦克风不可用或玩家临时修正内容时的兜底。
- Web Demo 先使用浏览器语音识别，把玩家发言转成文字后进入圆桌消息流；这样不需要后端保存音频，也能保留可复盘的文字记录。
- 后续多人游戏版本应升级为 WebRTC 或专用语音服务，支持实时语音房间、静音、音量、断线重连和空间化音效。
- AI 可以先以文字发言，后续再叠加 TTS 语音；文字记录仍然保留，方便复盘和身份推理。

## 游戏版本延续

- 如果未来做 3D/Steam 版本，身份标记应表现为玩家视角内的推理卡片、桌面便签或头像旁小徽章。
- “点人 -> 标记怀疑身份 -> 标记挂在头像下方”这个心智模型保持不变。
- 真实身份永远只在规则允许的时机展示，例如死亡翻牌、结算、或特定技能结果。

## 视觉节奏

- Web Demo 以流畅、稳定、清晰为第一优先级，避免复杂走位和不成熟的 3D 场景。
- 交互反馈要轻：hover、面板浮现、徽章高亮即可，不做会干扰阅读的持续动画。
- 座位、聊天、身份标记三件事是首屏重点，其余规则和配置收进侧栏或次级页面。

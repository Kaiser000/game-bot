# AI 人设知识库设计

当前人设知识库存放在：

```text
backend/app/personas.json
```

它的目标不是写死某个角色的一句台词，而是把“打法倾向”结构化，让同一个 AI 在不同身份、阵营、阶段下做出不同选择。

## 当前结构

```json
{
  "modes": [],
  "werewolf": [],
  "avalon": []
}
```

### modes

`modes` 是整局 AI 的打法方案，用于创建房间时选择：

- `balanced`：自动混合，适合常规 demo。
- `aggressive`：高压进攻，更多强推和质询。
- `deceptive`：诈身份实验，坏人更偏伪装、悍跳、带节奏。
- `conservative`：保守推理，重视票型、逻辑闭环和低风险表达。

### persona

每个人设包含：

- `id`：稳定标识。
- `name`：展示名，例如“倒钩狼”“冲锋狼”“悍跳狼”。
- `camp`：阵营，`good` 或 `evil`。
- `roles`：适用角色。
- `modes`：适用打法方案。
- `summary`：前端展示说明。
- `tags`：后端决策标签。
- `voice`：语言风格提示。

## 后端如何使用

创建房间时，前端传入：

```json
{
  "gameId": "werewolf",
  "targetPlayers": 12,
  "humanPlayers": 11,
  "personaMode": "deceptive"
}
```

后端会根据：

1. 游戏类型。
2. AI 的角色。
3. AI 的阵营。
4. 当前 `personaMode`。

为每个 AI 座位挑选一个 persona，并写入 seat：

```json
{
  "name": "AI-星野",
  "role": "狼人",
  "persona": {
    "id": "wolf_fake_seer",
    "name": "悍跳狼",
    "tags": ["fake_claim", "counter_claim", "make_story"]
  }
}
```

发言生成时，后端会读取 `tags`。例如：

- `fake_claim`：狼人更可能跳预言家或制造验人故事。
- `hard_push`：更容易强推某个目标。
- `bus_teammate`：狼人更容易轻踩同伴做倒钩。
- `merlin_hunt`：刺客更关注“知道太多但不敢明说”的人。
- `create_noise`：爪牙更倾向制造讨论噪音。

## 扩展建议

下一步可以继续加：

- 狼人杀：隐狼、深水狼、抗推村、强神、诈身份村民。
- 阿瓦隆：假派西、保梅忠臣、强势队长、反车专家。
- 血染钟楼：说书人风格、恶魔伪装、洗信息角色、保护关键好人。

长期可以把 persona 从“规则标签”升级成 LLM prompt 片段：

```text
你是倒钩狼。你知道自己是狼人，但你不能暴露身份。
你的目标是通过轻踩狼队友、站边部分好人来换取信任。
你要避免每轮都攻击同一个人。
```

这样当前规则驱动 demo 可以自然演进成真实 LLM 版本。

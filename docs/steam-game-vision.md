# 圆桌智核 Steam 化游戏愿景

## 一句话方向

把“AI 桌游补位”从网页工具升级成一款带沉浸式房间、角色表演、语音氛围和多人联机的社交推理游戏。玩家不是在网页里点按钮入座，而是以第一人称或近似第三人称视角走进一间真实存在的圆桌房间。

## 目标开场体验

1. 玩家点击加入房间后，画面从黑场淡入到一扇厚重的木门前。
2. 门把手转动，房门打开，房间里的暖光、阴影、桌面烛台和已入座角色逐渐出现。
3. 玩家走进房间，圆桌旁已经坐着多名角色：
   - 真人玩家的角色。
   - AI 补位角色。
   - 旁观者或主持人角色，后续可选。
4. 玩家进门瞬间，已入座角色同时转头看向玩家。
5. 玩家选择一个空座，角色走到座位旁并坐下。
6. 所有人入座后，房间灯光突然熄灭。
7. 圆桌中央点燃一支蜡烛，只照亮桌面和角色轮廓。
8. 旁白或主持人声音响起：“天黑请闭眼。”
9. 游戏进入夜晚阶段，角色动作、语音、UI 和 AI 行为全部切到当前桌游规则对应的流程。

## Web 端是否适合

Web 端可以做原型，但不适合作为最终 Steam 级产品的主战场。

适合 Web 的部分：

- 房间创建、邀请链接、规则配置。
- AI 发言和身份逻辑验证。
- 玩家入座、投票、发言等低成本交互原型。
- 早期用户测试和快速迭代。

不适合只靠 Web 承担的部分：

- 稳定的 3D 摄像机调度。
- 大量角色动画、转身、坐下、表情和眼神注视。
- 复杂灯光、阴影、后处理和恐怖/悬疑氛围。
- 语音空间化、音效同步、多人状态同步。
- Steam 平台能力，例如成就、好友邀请、Overlay、手柄、打包发行。

结论：当前 Web Demo 继续负责验证“桌游规则 + AI 补位 + 多人房间 + 人设打法库”。真正的沉浸式产品建议拆成独立游戏客户端。

## 推荐技术路线

### 短期：Web Demo 继续打磨核心玩法

- 保留当前 React + Python + LangChain 架构。
- 继续验证：
  - AI 是否会暴露身份。
  - 不同人设打法是否有差异。
  - 狼人杀、阿瓦隆等常见桌游的流程是否完整。
  - 多人入座、隐藏身份、发言、投票是否稳定。
- Web 端场景只做到“能表达概念”，不继续追求完整 3D 电影感。

### 中期：制作 Unity 或 Unreal 原型

推荐优先级：

1. Unity：开发效率高，Steam 发行资料多，适合中小团队快速做多人社交游戏。
2. Unreal：画面上限高，适合强氛围、电影化镜头和高质量灯光，但开发成本更高。
3. Godot：轻量、开源，但商业多人和高品质资产管线需要更多自研。

如果目标是“尽快做出可玩的 Steam Demo”，建议优先 Unity。

### 长期：Web 后端变成游戏服务

当前项目可演进为游戏服务端雏形：

- 房间管理。
- 玩家座位和身份。
- 桌游规则状态机。
- AI 人设和打法库。
- AI 发言生成。
- 对局日志和复盘。

Unity/Unreal 客户端只负责：

- 3D 房间。
- 角色表现。
- 摄像机和灯光。
- 语音、音效、UI。
- Steam 集成。

## 核心系统拆分

### 1. 房间叙事系统

负责开门、入场、落座、灯灭、蜡烛点燃、旁白等流程。

关键状态：

- `door_closed`
- `door_opening`
- `entering_room`
- `characters_turning`
- `choosing_seat`
- `walking_to_seat`
- `seated`
- `lights_out`
- `candle_lit`
- `night_started`

### 2. 角色表现系统

每个角色需要基础动作：

- Idle 坐姿。
- 转头看向门口。
- 看向发言者。
- 低头闭眼。
- 举手或投票。
- 起身、落座。
- 轻微紧张、怀疑、思考等循环动作。

AI 角色不只是“发文字”，还要在画面里表现出性格：

- 冲锋型：动作更主动，发言时身体前倾。
- 倒钩型：更克制，常观察队友。
- 悍跳型：发言时更有压迫感。
- 保守型：动作少，常低头思考。

### 3. 灯光与氛围系统

开局阶段：

- 暖色吊灯。
- 壁炉或烛台补光。
- 角色脸部有柔和边缘光。

夜晚阶段：

- 主灯熄灭。
- 圆桌中央蜡烛成为唯一主光源。
- 角色大多变成轮廓，只保留眼睛、手部或身份相关微弱高光。
- 旁白进入，UI 降低亮度。

### 4. 规则和 AI 系统

继续沿用当前项目的方向：

- 规则状态机控制阶段。
- 真人玩家身份只对本人可见。
- AI 根据身份、阵营、人设打法和历史发言生成行为。
- 对局日志可用于复盘，也可用于训练更好的人设策略。

## Steam 版 MVP

第一版 Steam Demo 不必支持所有桌游，建议只做一个强体验闭环：

- 一个 8-10 人狼人杀板子。
- 支持真人 + AI 混合入座。
- 有完整房间入场演出。
- 有夜晚闭眼和白天发言两个强氛围阶段。
- 真人玩家语音优先，文字记录作为复盘和兜底。
- AI 能根据人设发言和投票。
- 完成一局后有复盘。

## 当前 Web 项目的可复用价值

可以复用：

- Python 后端房间模型。
- 桌游规则数据。
- AI 人设打法库。
- LangChain 模型接入。
- 对局消息结构。
- 市场调研和效果报告。

不建议复用为最终形态：

- 当前 React 场景层。
- 纯网页 CSS 动画。
- Web 端伪 3D 入座交互。

这些更适合作为产品概念验证，而不是最终游戏客户端。

## 后续待定问题

- 游戏视角：第一人称、第三人称，还是固定电影镜头。
- 角色风格：写实、哥特卡通、动物拟人、还是桌游手办风。
- AI 是否只文字发言，还是文字 + 合成语音同步输出。
- Steam 版是否需要独立账号，还是只用 Steam ID。
- 服务端是否继续 Python，还是拆出独立实时同步服务。
- 是否要做主持人模式，让真人可以当上帝视角主持。

## 产品定位

这不只是“桌游 AI 补位工具”，更像是：

> 一款让 AI 成为桌上真实玩家的沉浸式社交推理游戏。

当前 Web Demo 负责把 AI 玩得像人。未来 Steam 版负责让玩家感觉自己真的走进了一间危险、神秘、有人在撒谎的圆桌房间。
